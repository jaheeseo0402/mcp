# 4번 정리 — AFL식 공통 틀에서 mcp-fuzzer · 기존 퍼저 · 제안 모델 비교

## 교수님 질문
"AFL 틀(오픈소스? AFL/AFL++? 수정 가능?) 위에서 mcp-fuzzer, 기존 퍼저, 제안 모델을 같은 환경·같은 지표(크래시 등)로 비교하라."

## 한 줄 답
진짜 AFL/AFL++는 Node 서버(V8)에 붙일 수 없어서 **AFL의 동작 방식(큐 → 변이 → 호출 → 새 커버리지면 큐에 추가)을 직접 구현한 틀(`kit/afl_fuzz.py`)**을 만들었고, 그 안에서 변이 전략만 바꿔 같은 초기 시드·같은 호출 수·같은 지표로 비교했다.

## 1. 왜 진짜 AFL/AFL++를 못 썼나 (직접 시험·확인한 것)
| 퍼저 | 결과 | 이유 |
|---|---|---|
| AFL / AFL++ | 붙지 않음 | 파일·표준입력으로 받는 네이티브 프로그램용(소스 컴파일 계측 또는 QEMU). Node 서버는 V8 JIT라 계측 경로가 없다. |
| AFLNet | 시험 안 함 | 네트워크 프로토콜 서버용. MCP stdio 전송과 안 맞는다. |
| Jazzer.js 4.0.0 | 서버 수정본으로만 붙음 (예비) | 같은 프로세스에서 로드한 JS에만 계측. 서버를 InMemoryTransport로 구동하도록 고친 사본에서 60초 시험: 444,893회 실행, 폴더 밖 성공 0 (폴더 정보 없이는 우리 black-box 결과와 같은 방향). 시드 1개·서버 1개라 결론 아님. |

## 2. 공통 틀 (같은 것 / 다른 것)
- 같은 것: 초기 시드, 큐, 피드백(V8 신규 커버리지), 호출 수(도구당 1,000회), 서버, 서버별 시드 10개.
- 다른 것(변이 전략만): Random(havoc) / mcp-fuzzer(0.7.0 입력 생성 로직 이식 65% + havoc) / 제안(서버 폴더를 읽어 경로형 필드에 경로 이탈·경계값·유효·준유효 입력 각 25%).
- 서버: mcp-server-filesystem 0.6.2(접두어 검사 결함 있음), @agent-infra 1.2.29(결함 있음), @adpharm-ro 0.1.2(읽기 전용, 결함 없음 = 대조).
- 지표: 입력 검증 통과율, 정상 실행률, 경로 이탈 성공 횟수, 고유 (도구, 폴더) 쌍, V8 커버리지, 크래시. 통계는 95% 구간, Mann-Whitney U 단측.

## 3. 결과 (내 환경에서 재현, 평균±95% 구간)
**일반 시드**
| 서버 | 지표 | Random | mcp-fuzzer(이식) | 제안 |
|---|---|---|---|---|
| old | 경로 이탈 성공 | 0.0 | 0.0 | 25.2±2.9 |
| old | 커버리지 | 228.0 | 232.0 | 303.7±1.0 |
| agent-infra | 경로 이탈 성공 | 0.0 | 0.0 | 36.9±4.8 |
| agent-infra | 커버리지 | 785.0 | 790.0 | 856.4±0.5 |
| adpharm-ro | 경로 이탈 성공 | 0 | 0 | 0 (결함 없는 서버 = 아무거나 뚫지 않음) |

**시작 입력을 실제 경로로 유리하게 줘도** (공정성 확인): old 0.1 / 1.3 / 24.7, agent 0.1 / 0.5 / 35.0 → 결론 동일, 모든 비교 p<0.001.

**진짜 mcp-fuzzer 0.7.0 도구 그대로** (시드 5개): 경로 이탈 성공 0, 커버리지 old 272.0, agent 809.0 → 이식이 약점을 만든 게 아님. 커버리지는 이식보다 높지만 제안보다 낮다(p<0.002).

**LLM 입력 생성 조건 추가** (자동 생성 프롬프트, 응답 그대로 붙여넣기, 정보량은 제안과 같게: 서버 폴더 구조 + 바로 옆 폴더 이름)
| 서버 | llmblind(정보 없음) | llmtree(폴더 정보) | 제안 |
|---|---|---|---|
| old | 0.0 | 193.5±66.5 | 25.2±2.9 |
| agent | 0.0 | 254.3±5.9 | 36.9±4.8 |
→ 폴더 정보 없는 LLM은 0, 폴더 정보 있는 LLM은 제안보다 많다. 커버리지는 같다.

**요소 제거(ablation)**: 경로 이탈 입력을 빼면 23.7 → 0.0(시드 6개 모두 0). 경계값·유효·준유효를 빼도 경로 이탈 성공은 줄지 않는다(오히려 늚).

## 4. 이 결과로 말할 수 있는 것 / 없는 것
말할 수 있다:
- 서버 폴더 정보를 입력 생성에 쓰면, 기존 방식(Random, mcp-fuzzer)이 0이던 폴더 검사 결함(접두어 우회)을 같은 AFL식 틀·같은 호출 수에서 찾는다.
- 효과는 **경로 이탈 입력**에서 나온다. 결함 없는 서버에서는 0이다.
- 폴더 정보 없이는(black-box, llmblind) 0이다.

말할 수 없다:
- "4종류 규칙이 LLM보다 낫다" → 반대로 정보량이 같은 LLM이 더 많이 찾았다. 주장하지 않는다(사전 판정 기준 적용).
- "진짜 AFL++ 대비 우월" → 진짜 AFL++는 못 돌렸다.
- "취약점을 더 많이 찾는다" → 크래시 0건, 한 종류(경로 검사)만 검증.

## 5. 한계 (정직하게)
1. AFL식 틀은 직접 구현(진짜 AFL++ 아님). 교수님께 이 정도로 충분한지 확인 필요.
2. 크래시 지표는 오류 문구만 봐서 프로세스 종료 감지가 없고 전부 0.
3. Jazzer.js는 예비 시험(1서버·시드 1개·수정본).
4. 시드 수가 다르다: 진짜 도구 5개, 나머지 10개, 이전 논문 표는 12회.
5. LLM은 1종·프롬프트 1개·풀 1개 공유(변동성 미반영). 사용한 모델명 기입 필요.
6. 그레이박스 가정(서버 폴더를 읽는다), 서버 3개, 결함 1종류.
