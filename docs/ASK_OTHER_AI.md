학부 3학년 두 명(KCSE 투고 목표)의 연구입니다. 1차판으로 받은 조언(실제 파일 접근 오라클, 정보량 통제, 이름 무작위화, 대응표본 검정)을 반영해 실험을 다시 했고, 결과가 연구 방향을 바꿀 만큼 달라졌습니다. 숫자는 전부 직접 돌린 실제 결과이고, 약한 점도 그대로 적었습니다. 예산 없음(유료 API 불가), WSL2 Ubuntu, 터미널 초보. 코드·원자료·표 전부: https://github.com/jaheeseo0402/mcp

## 0. 연구 한 줄
MCP 파일시스템 서버의 "허용 폴더 밖 접근 차단" 결함(접두어 검사 우회, `startsWith`, CVE-2025-53110과 같은 종류)을 퍼징으로 찾는 연구. 원래 제안은 서버 폴더를 읽어 경로 입력 4종류(경로 이탈/경계값/유효/준유효 각 25%)를 만드는 입력 생성기였고, Random과 mcp-fuzzer 0.7.0과 비교했다.

## 2. 이번에 한 일 (순서)
1. **보안 오라클 교체**: 기존 "경로 이탈 성공"은 서버가 오류 없이 응답했고 경로 인자가 허용 폴더 밖이면 센 것이라 실제 접근을 증명하지 못했다(다른 AI의 지적 + 코드 확인). 허용 폴더 밖 파일에 실행마다 다른 난수 토큰을 심고, 호출마다 ① 응답에 토큰 노출(`leak`) ② 밖 파일시스템 지문 변화(`mutate`) ③ 밖에만 있는 파일 이름이 목록에 나옴(`list`)으로 판정.
2. 경로 필드 판별 기준을 퍼저·분석기가 공유하도록 통일, 통계를 시드 짝지은 Wilcoxon + 부트스트랩으로 변경(시드 10개 단측 최소 p=0.001이라 "p<0.001" 불가).
3. **정보 수준 실험**: 같은 입력 생성기에 아는 정보를 0~4단계로 줌 — L0 없음 / L1 허용 폴더 경로만 / L2 +폴더 내부 구조 / L3 +이웃 폴더 이름 / L4 +이웃 폴더 안 파일 이름. 생성 방식 둘: `four`(4종류 25%) vs `rand`(같은 정보의 이름을 무작위 접두어(`../`, 부모 경로 등)에 붙여 조합만 함, 대조군).
4. **이름 무작위화**: 시드마다 허용 폴더·접두어를 공유하는 이웃 폴더·비밀 파일 이름을 고정 목록에서 추출해 바꿈. 결과를 보기 전에 판정 기준을 문서에 고정.

## 3. 실제 결과 (서버 2종: mcp-server-filesystem 0.6.2 "old", @agent-infra 1.2.29 "agent"; 서버당 도구별 1,000호출; 평균±95% 구간)
**3-1. 실제 효과 기준 위반, 시드 10개, 일반 시드** — 응답 기반 숫자는 실제보다 컸다.
| 서버 | 지표 | Random | mcp-fuzzer(0.7.0 입력 생성기 이식) | 제안(4종류, 이웃 폴더 이름까지) |
|---|---|---|---|---|
| old | 실제 위반 호출(viol) | 0 | 0 | 20.4±15.7 |
| old | (비교) 응답 기반 | 0 | 0 | 25.2±2.9 |
| agent | 실제 위반 호출 | 0 | 0 | 24.8±3.2 |
| agent | (비교) 응답 기반 | 0 | 0 | 36.9±4.8 |
위반의 대부분은 `list_directory`/`search_files`/`directory_tree`의 밖 폴더 목록 노출이고, `move_file`로 밖 파일시스템이 실행당 약 1회 변경됨. **비밀 토큰 노출은 0**(제안은 이웃 폴더 이름까지만 알고 그 안 파일 이름은 모름). 시드 짝지은 검정에서 제안 > Random·mcp-fuzzer, 평균 차 구간이 0 위.

**3-2. 정보 수준별(이름 고정, 시드: L0~L2는 3개(전부 0), L3·L4는 10개)**
| 서버 | 수준 | 생성 | viol | leak | mutate |
|---|---|---|---|---|---|
| 둘 다 | L0~L2 | four·rand | 0 | 0 | 0 |
| old | L3 | four / rand | 15.0 / 27.5 | 0 / 0 | 0.8 / 0.9 |
| old | L4 | four / rand | 26.9 / 62.5 | 7.2 / 18.3 | 9.7 / 24.2 |
| agent | L3 | four / rand | 27.7 / 50.3 | 0 / 0 | 0.9 / 0.8 |
| agent | L4 | four / rand | 32.8 / 86.3 | 7.2 / 18.3 | 10.0 / 26.4 |
- 정보를 L3→L4로 늘리면 leak·mutate가 새로 생기고 시드 10개에서 일관(p=0.001).
- 같은 정보에서 `rand`가 `four`보다 위반을 유의하게 많이 일으킴(four−rand 구간이 0 아래). 반면 `four`는 정상 처리율(23~24% vs 14~16%)과 커버리지가 더 높고 고유 위반 종류 수는 거의 같음. `rand`는 경로 이탈 시도 비중이 더 높아서일 수 있음(이전 실험에서 위반 ≈ 경로 이탈 비중에 비례). 비중을 맞춘 비교는 아직 안 함.

**3-3. 이름 무작위화(시드 10개, L3·L4)**: 위 3-2와 거의 같은 값(예: old L4 four viol 26.7, leak 6.4; agent L4 rand viol 83.3). 이름과 무관하게 패턴 유지.

**3-4. 이전 단계 결과(응답 기반 지표 시절)**: 블랙박스(폴더 정보 없음)에서는 제안도 0. 같은 정보의 LLM(응답 붙여넣기, 1회 생성 풀, 모델명 미기록)이 제안보다 폴더 밖 성공을 훨씬 많이 만듦(old 193.5 vs 25.2, agent 254.3 vs 36.9) — 단 LLM 조건은 **아직 새 오라클로 재측정 안 함**. 진짜 mcp-fuzzer 도구를 그대로 돌려도 0(시드 5개). 폴더 구조를 모르는 LLM은 0.

## 4. 현재 내 결론과 확신 정도
- 비교적 확실: 이 두 서버·이 결함에서 위반 발견은 알고리즘이 아니라 **서버 구조 정보를 어디까지 쓰느냐**가 갈랐다. 이름을 바꿔도 유지.
- 접었음: "4종류 구성이 위반 발견에 필요하다"(같은 정보에서 단순 조합이 더 많이 찾음).
- 남은 4종류의 장점: 정상 처리율·커버리지(깊이). 위반 수는 아님.
- 새 방향 후보: 새 기법 제안이 아니라 "서버 구조 정보 수준이 경로 접근 제어 결함 탐지에 미치는 영향의 통제 실증 연구".

## 5. 약한 점 (이대로면 심사위원이 공격할 것)
1. 새 알고리즘적 기여가 없다. 결과의 핵심이 "이웃 폴더·파일 이름을 알면 그 이름으로 경로를 만들 수 있다"는, 직관적으로 당연해 보이는 효과일 수 있다("당연한 것 아닌가").
2. 서버 2종(+ 읽기 전용 대조 1종), 결함 1종류(접두어 우회). L3·L4 시드 10개, 정확 검정 최소 p=0.001.
3. 정보 L3는 호스트 파일시스템을 직접 읽는 gray-box 가정이다. 실제 black-box 환경에서 MCP 도구(`list_directory` 등)를 먼저 호출해 이 정보를 스스로 얻는 적응형 방식은 구현·검증 안 함.
4. 추측 이름(`etc tmp backup data private home`)과 접미사·파일 이름 목록이 고정 목록이다(완전 임의 문자열 아님).
5. 진짜 AFL++ 비교 불가(재구현), 크래시 지표 부실(프로세스 종료 감지 없음, 전부 0), Jazzer.js는 예비.
6. LLM 조건: 모델명 미기록, 풀 1개 재사용, 새 오라클 재측정 안 함. 위 3-4는 응답 기반 시절 결과.
7. 선행 연구 ToFu(arXiv 2610.13651), MCP-FSD(arXiv 2610.22301, 접두어 일치 우회 + 외부 비밀 파일 + 동적 검증을 이미 다룸), VIPER-MCP, Park & Baek(2025)과의 전문 대조 미완. MCP-FSD와 겹침이 크다고 판단함.

## 7. 질문
1. 위 결과로 "서버 구조 정보 수준의 영향을 통제 실험으로 실증"하는 기여가 KCSE급(국내 학회)에서 충분한가? 부족하다면 **가장 적은 작업으로 기여를 가장 크게 올리는 한 가지**는? (후보: ① 적응형 정보 수집(블랙박스에서 도구로 구조 알아내기) ② 서버 수 확대(공개 MCP 파일시스템 서버 10개 이상 측정) ③ 취약/패치 버전 비교 ④ LLM 조건을 새 오라클로 3~5개 독립 풀 재측정 ⑤ 결함 종류 확장 ⑥ 새 취약점 발견·책임 있는 제보)
2. "당연한 것 아닌가" 공격에 대한 가장 좋은 대응은? (정보 수준 문턱을 정량화하는 것이 새로운가? 도구별로 필요한 정보가 다르다는 분석은?)
3. 4종류 구성은 위반 수에서 졌다. 연구에서 어떻게 처리하는 게 정직하고 득이 되는가(제거, 부차 결과로 강등, 깊이 지표로 재포지셔닝)?
4. ToFu·MCP-FSD와 차별화되는 현실적인 지점이 있다면 무엇인가? 없다면 어떻게 위치시켜야 하는가?
5. 실험 설계에서 내가 놓친 타당성 위협(threats to validity)과, `rand`가 더 많이 찾은 것을 공정하게 해석하려면 어떤 통제(경로 이탈 비중 맞추기 등)가 필요한가?
6. 4주 안에 할 수 있는 현실적 일정안(우선순위·난이도 표기).
