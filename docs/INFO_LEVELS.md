# 2단계: 정보 수준별 비교 (결과를 보기 전에 작성, 2026-11-23)

## 질문
RQ-A. 서버 구조 정보를 어디까지 알면 허용 폴더 경계 위반이 실제로 일어나는가?
RQ-B. 같은 정보를 쓸 때 4종류 구성(경로 이탈·경계값·유효·준유효 각 25%)은 "아는 이름을 무작위로 조합"하는 단순 방식보다 나은가?

## 조건 (`kit/run_info.sh`, `--strategy info`)
정보 수준(아는 것): L0 없음 / L1 허용 폴더 경로만 / L2 +폴더 내부 구조 / L3 +이웃 폴더 이름 / L4 +이웃 폴더 안 파일 이름.
생성 방식: `four` = 4종류 25% / `rand` = 같은 정보의 이름을 무작위 접두어(없음, `../`, `../../`, 허용 폴더 경로, 부모 경로)에 붙여 조합만 함(대조).
모르는 이름 대신 쓰는 추측은 고정 목록 `etc tmp backup data private home`(실험 전에 정함). 나머지 필드는 havoc, 초기 시드·큐·피드백·호출 수 동일. 판정은 `docs/ORACLE.md`의 오라클.

## 사전 판정 기준
- `rand` ≥ `four` (같은 정보 수준에서 viol 차이의 95% 구간이 0을 포함하거나 rand가 높음) → "4종류 구성이 필요하다"는 주장을 하지 않고 "정보 수준이 결정한다"로만 쓴다.
- `four` > `rand` (구간이 0 위) → 4종류 구성의 효과를 주장하되 정보 수준 조건과 함께 쓴다.
- 이 결과에 맞춰 생성기를 고치지 않는다. 고치면 새 서버·무작위 폴더 이름(3단계)으로 재검증한다.

## 알려진 한계
- 폴더 이름(`sandbox_secret`, 파일 `secret.txt`)이 고정이다. 3단계에서 이름을 무작위화한다.
- 서버 2종(old, agent), Node.js 파일시스템 서버 한정. 읽기 전용 서버(adro)는 결함이 없어 제외.
- LLM 조건은 이 2단계에 아직 없다(붙여넣기 방식이라 정보 수준별로 풀을 따로 만들어야 함).

## 스모크 테스트 (old, 시드 1, 도구당 500, 정식 결과 아님)
| 조건 | 오라클 위반 |
|---|---|
| four L0 | 없음 |
| four L3 | list_directory list 7 |
| four L4 | read_file leak 2, write_file mutate 1, move_file mutate 2, list_directory list 4 |
| rand L4 | read_file leak 14, write_file mutate 10, move_file mutate 3, list_directory list 9 |
시드 1개라 결론 아님. L4에서 처음으로 파일 내용 노출(leak)과 파일 쓰기(mutate)가 나타났고, 이 호출 수에서는 rand가 four보다 많았다 — 정식 실험에서 확인한다.

관찰
1. **정보 수준이 문턱을 만든다.** L0(정보 없음)~L2(허용 폴더와 내부 구조까지)에서는 두 생성 방식 모두 위반 0. 이웃 폴더 이름을 아는 L3에서 처음 목록 노출(list)이 나타나고, 이웃 폴더 안 파일 이름을 아는 L4에서 처음 파일 내용 노출(leak)과 밖 파일 변경(mutate)이 나타난다. 두 서버에서 같은 양상.
2. **사전 판정 기준 적용: 같은 정보에서 `rand` ≥ `four`.** L3·L4에서 `rand`의 viol이 `four`의 약 2배이고 차이의 95% 구간이 0보다 아래(두 서버·3시드 모두 같은 방향). 따라서 "4종류 구성이 위반 발견에 필요하다"는 주장은 하지 않는다. 고유 위반 종류 수(vuniq)는 거의 같아(old L4 4.7 vs 4.7, agent L4 5.3 vs 6.0) `rand`는 같은 종류를 더 자주 일으킨다.
3. 해석상 주의: `rand`는 알려진 이름에 `../`·부모 경로를 붙이는 조합이라 호출 중 경로 이탈 시도 비율이 `four`(25%)보다 높다. 이전 비율 민감도 실험(위반 ≈ 경로 이탈 비중에 비례)과 일치하므로, `rand`가 더 똑똑한 것이 아니라 경로 이탈 비중이 큰 것일 수 있다. 경로 이탈 비중을 맞춘 비교는 하지 않았다.
4. `four`가 나은 쪽은 위반 수가 아니라 정상 처리율(22~24% vs 10~16%)과 커버리지(정보가 적을 때 특히: L1 old 303 vs 259)이다. 4종류 구성의 효과를 주장한다면 이 쪽(깊이)이다.
5. L0~L2의 0은 생성기에 접두어 충돌 추측(허용 폴더 이름 + 일반 접미사)을 넣지 않았기 때문이기도 하다. 폴더 이름이 고정이라는 한계와 함께 3단계(이름 무작위화)에서 확인한다.
6. old L3·L4의 `four`는 구간이 크다(예: viol 16.0±12.9). 시드 3개라 불안정하다.
