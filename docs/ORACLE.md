# 보안 오라클 (응답 기반 → 실제 파일시스템 기반) — 2026-11-23

## 왜 바꿨나
기존 "경로 이탈 성공"은 ① 오류 없이 응답했고 ② 경로 인자가 허용 폴더 밖으로 정규화되면 셌다. 서버가 실제로 밖의 파일을 읽거나 바꿨는지는 확인하지 않았다 (외부 검토 지적 + 코드 확인). 기존 지표는 `out`(응답 기반, 비검증)으로 남기고, 실제 효과를 보는 `viol`을 추가했다.

## 판정 (afl_fuzz.py가 호출마다 기록 → calls.jsonl의 `viol`, `eff`)
- `leak`: 허용 폴더 밖 파일에 심은 **실행마다 다른 난수 토큰**이 (오류 아닌) 응답에 나옴
- `mutate`: 호출 전후 허용 폴더 밖 파일시스템 지문(파일 내용 해시 + 폴더 구조)이 달라짐 = 실제 생성·수정·삭제·이동
- `list`: 밖에만 있는 파일 이름(secret.txt, data.txt)이 목록 응답에 나옴 (인자에 그 이름이 없을 때만)
- 미검증: get_file_info의 메타데이터 노출은 아직 오라클이 없음(응답 기반 `out`에만 남음). `run_real_tool.sh`(진짜 mcp-fuzzer 도구)와 LLM 스크립트는 아직 이 오라클을 쓰지 않음.

## 함께 고친 것
- 경로 필드 판별 기준을 `common.py` 하나로 통일 (퍼저는 file/dir/folder/target까지, 분석기는 path/source/destination/repo_path만 보던 불일치 해소).
- 통계: 시드 번호가 같은 조건끼리 **대응표본** Wilcoxon 부호순위(단측) + 평균 차이의 95% 부트스트랩 구간. 시드 10개일 때 단측 정확 검정의 최소 p는 약 0.001이므로 "p<0.001"은 시드 20개 이상에서만 쓸 수 있다.

## 스모크 테스트 (내 환경, old 서버, 비교용 소규모, 정식 결과 아님)
| 실행 | 도구당 호출 | out(응답 기반) | viol(실제 효과) | 종류 |
|---|---|---|---|---|
| ours, 시드 1 | 150 | 8 | 4 | list 4 (list_directory) |
| ours, 시드 2 | 600 | (미집계) | 4 | list 4 (list_directory) |
| random, 시드 1 | 150 | 0 | 0 | |

해석(예비): 응답 기반 지표는 실제 효과보다 크게 셌다(8 vs 4). 실제로 확인된 위반은 허용 폴더 밖 디렉터리 목록 노출(list_directory)이었고, 이 호출 수에서는 비밀 토큰 노출이나 밖의 파일 변경은 관찰되지 않았다. 시드·호출 수가 작아 결론이 아니다. 정식 결과는 `OUTD=runs_oracle bash run_afl.sh generic ...`(시드 10개 이상)로 다시 측정해야 한다.

## 정식 결과 — 오라클 기반 (재현자 환경, generic 시드, 서버별 시드 10개, 도구당 1000회)
실행: `OUTD=runs_oracle bash run_afl.sh generic "old agent" "1..10"` → `RUNS=runs_oracle bash analyze.sh "old agent"`. 평균±95% 구간(괄호는 중앙값).
`out`(응답 기반)은 이전 결과와 같다(25.2±2.9, 36.9±4.8; 커버리지도 동일) → 오라클 추가가 실행 경과를 바꾸지 않았다.

| 서버 | 지표 | Random | mcp-fuzzer(이식) | 제안 |
|---|---|---|---|---|
| old | viol(실제 효과 위반 호출) | 0.0 | 0.0 | 20.4±15.7 (중앙 14.0) |
| old | 그중 list / mutate / leak | 0 / 0 / 0 | 0 / 0 / 0 | 19.4 / 1.0 / 0.0 |
| old | 고유 (도구,종류) | 0.0 | 0.0 | 2.2±0.3 |
| old | out(응답 기반, 비검증) | 0.0 | 0.0 | 25.2±2.9 |
| agent | viol | 0.0 | 0.0 | 24.8±3.2 (중앙 24.0) |
| agent | 그중 list / mutate / leak | 0 / 0 / 0 | 0 / 0 / 0 | 23.9 / 0.9 / 0.0 |
| agent | 고유 (도구,종류) | 0.0 | 0.0 | 3.5±0.4 |
| agent | out(응답 기반, 비검증) | 0.0 | 0.0 | 36.9±4.8 |

대응표본 Wilcoxon(단측, n=10): viol 제안>mcp-fuzzer, 제안>Random 모두 p=0.0010(이 n에서의 최솟값). 평균 차이 95% 부트스트랩 구간: old +20.4 [+11.8,+35.0], agent +24.8 [+22.4,+27.5].

해석
1. 응답 기반 지표는 실제 위반보다 old에서 약 19%(25.2→20.4), agent에서 약 33%(36.9→24.8) 크게 셌다. 순위(제안만 발견)는 바뀌지 않았다.
2. 실제로 확인된 위반은 거의 전부 허용 폴더 밖 **디렉터리 목록 노출(list)** 이고, 실행당 약 1회 허용 폴더 밖 파일시스템 변경(mutate)이 있었다. **비밀 토큰이 응답에 나온 경우(leak)는 0건** — 제안 모델은 이웃 폴더 이름까지만 알고 그 안의 파일 이름을 몰라서 파일 내용을 읽지 못한다. "비밀 파일 내용 유출"을 주장할 수 없다.
3. old 서버 viol의 시드 간 편차가 크다(±15.7, 중앙 14).
4. `first`(첫 위반까지 호출 번호)는 도구별 순차 실행 구조라 발견 속도가 아니라 도구 순서를 반영한다. 도구별 첫 위반으로 다시 정의해야 한다. (단측 검정의 p=1.0은 낮을수록 좋은 지표에 방향을 반대로 둔 결과일 뿐 의미 없음.)
5. 시드 10개 단측 정확 검정의 최소 p가 0.001이므로 "p<0.001"이라고 쓸 수 없다.

### 도구별 위반 (시드 10개 합계, 제안 모델만 발생. Random·mcp-fuzzer는 전 도구 0)
| 서버 | list_directory (list) | search_files (list) | directory_tree (list) | move_file (mutate) |
|---|---|---|---|---|
| old | 128 | 66 | 0 | 10 |
| agent | 117 | 9 | 113 | 9 |

- 읽기 계열(list_directory, search_files, directory_tree)에서 밖 폴더의 파일 이름이 노출됐다. move_file은 시드마다 정확히 1번(허용 폴더 밖 파일시스템 변경, 10시드 중 old 10, agent 9).
- read_file·write_file·get_file_info·edit_file 등에서는 오라클 기준 위반이 없었다 (제안 모델이 밖 폴더 안의 파일 이름을 모르므로 파일 내용 읽기·쓰기 입력을 만들지 못함).
- move_file이 시드당 1번뿐인 이유(첫 이동 후 원본이 사라져 이후 같은 이동이 변경을 일으키지 못함)는 추정이며 calls.jsonl의 `eff` 필드로 확인 필요.
