# 보안 오라클 (응답 기반 → 실제 파일시스템 기반) — 2026-11-23

## 왜 바꿨나
기존 "경로 이탈 성공"은 ① 오류 없이 응답했고 ② 경로 인자가 허용 폴더 밖으로 정규화되면 셌다. 서버가 실제로 밖의 파일을 읽거나 바꿨는지는 확인하지 않았다 (외부 검토 지적 + 코드 확인). 기존 지표는 `out`(응답 기반, 비검증)으로 남기고, 실제 효과를 보는 `viol`을 추가했다.

## 판정 (afl_fuzz.py가 호출마다 기록 → calls.jsonl의 `viol`, `eff`)
- `leak`: 허용 폴더 밖 파일에 심은 **실행마다 다른 난수 토큰**이 (오류 아닌) 응답에 나옴
- `mutate`: 호출 전후 허용 폴더 밖 파일시스템 지문(파일 내용 해시 + 폴더 구조)이 달라짐 = 실제 생성·수정·삭제·이동
- `list`: 밖에만 있는 파일 이름(secret.txt, data.txt)이 목록 응답에 나옴 (인자에 그 이름이 없을 때만)
- 미검증: get_file_info의 메타데이터 노출은 아직 오라클이 없음(응답 기반 `out`에만 남음). `run_real_tool.sh`(진짜 mcp-fuzzer 도구)와 LLM 스크립트는 아직 이 오라클을 쓰지 않음.

## 함께 고친 것
- 경로 필드 판별 기준을 `common.py` 하나로 통일 (퍼저는 file/dir/folder/target까지, 분석기는 path/source/destination/repo_path만 보던 불일치 해소).
- 통계: 시드 번호가 같은 조건끼리 **대응표본** Wilcoxon 부호순위(단측) + 평균 차이의 95% 부트스트랩 구간. 시드 10개일 때 단측 정확 검정의 최소 p는 약 0.001이므로 "p<0.001"은 시드 20개 이상에서만 쓸 수 있다.

## 스모크 테스트 (내 환경, old 서버, 비교용 소규모, 정식 결과 아님)
| 실행 | 도구당 호출 | out(응답 기반) | viol(실제 효과) | 종류 |
|---|---|---|---|---|
| ours, 시드 1 | 150 | 8 | 4 | list 4 (list_directory) |
| ours, 시드 2 | 600 | (미집계) | 4 | list 4 (list_directory) |
| random, 시드 1 | 150 | 0 | 0 | |

해석(예비): 응답 기반 지표는 실제 효과보다 크게 셌다(8 vs 4). 실제로 확인된 위반은 허용 폴더 밖 디렉터리 목록 노출(list_directory)이었고, 이 호출 수에서는 비밀 토큰 노출이나 밖의 파일 변경은 관찰되지 않았다. 시드·호출 수가 작아 결론이 아니다. 정식 결과는 `OUTD=runs_oracle bash run_afl.sh generic ...`(시드 10개 이상)로 다시 측정해야 한다.
