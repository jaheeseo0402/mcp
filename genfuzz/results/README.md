# 일반 퍼징 실험 결과 (구조정보 단계 L0~L3)

작성 시점 2026-11-27. 아래 숫자는 `exif/exif3_summary.csv`, `exif/llm_chat-A_summary.csv`, `exif/cmp_chat-A_summary.csv`에서 왔다.
MCP 퍼징은 이 문서에 포함하지 않는다.

## 1. 실험 설정

| 항목 | 내용 |
|---|---|
| 타깃 | libexif 0.6.14 (EXIF 읽기 라이브러리) + 하네스 `genfuzz/exif/harness.c` (파일을 읽어 태그 값을 문자열로 바꾸고 다시 저장) |
| 퍼저 | AFL++ 4.33c (afl-cc PCGUARD 계측), 한 번 10분(`-V 600`), 시드 번호 `-s <반복 번호>` |
| 환경 | WSL2 Ubuntu 26.04, CPU 8코어, 8개씩 동시 실행 |
| 반복 | L2, L3는 각 10번, L0, L1은 각 3번 (L0, L1은 3번 모두 결과가 같아 더 돌리지 않음) |
| 단계 정의 | L0 정보 없음(1바이트 시드 `A`) / L1 JPEG 시그니처(`FF D8 FF E1`) / L2 L1 + 필드 구조(APP1 길이, `Exif\0\0`, TIFF 헤더 머리 + 사전 `-x dict.txt`) / L3 L2 + 유효 EXIF 샘플 3개 |
| crash 구분 | `exifbin_tri`(같은 코드에 시그널 처리를 넣은 분류용 바이너리)로 crash 입력을 다시 실행해 호출 스택 위쪽 함수 이름을 얻고, `신호 + 맨 위 함수`가 같으면 같은 버그로 센다 |
| 중복 판단 | 파일 내용이 아니라 afl-showmap으로 얻은 edge 집합이 같은지 |

## 2. 실험 1: 구조정보 단계별 퍼징 (`exif/exif3_*.csv|png`)

10분 시점, 평균 (L2, L3는 n=10, L0, L1은 n=3)

| 단계 | 전체 crash | 고유 crash | 서로 다른 버그(맨 위 함수) | edge |
|---|---|---|---|---|
| L0 | 0 | 0 | 0 | 153~156 |
| L1 | 0 | 0 | 0 | 153~156 |
| L2 | 155.4 | 4.9 | 1.7 | 441.5 |
| L3 | 95.1 | 6.9 | 2.0 | 479.2 |

L2 대 L3 (Mann-Whitney 양측 검정, n=10 대 10)

| 지표 | p값 | 판단 |
|---|---|---|
| edge | 0.0006 | L3가 많음 |
| 고유 crash | 0.043 | L3가 많음 (경계) |
| 서로 다른 버그 수 | 0.33 | 차이 없음 |
| 전체 crash | 0.041 | L2가 많음 (같은 얕은 버그를 반복해서 터뜨린 횟수라 "많을수록 좋다"로 읽지 않는다) |

버그 위치별로 몇 번의 실행(10번 중)에서 찾았는가

| 버그 위치 | L2 | L3 |
|---|---|---|
| `exif_get_sshort` | 10 | 10 |
| `exif_get_slong` | 1 | 7 (Fisher 정확 검정 p=0.02) |
| `+0xad03` (이름 없는 내부 함수) | 6 | 3 (차이 없음) |

해석
- L0, L1은 10분 동안 crash를 하나도 못 찾았다. 시그니처만으로는 EXIF 파서 안으로 못 들어간다. 필드 구조를 주는 L2부터 crash가 나온다.
- L3는 코드를 더 깊이 탐색하고(edge, 고유 crash), 깊은 버그(`exif_get_slong`)를 훨씬 자주 찾았다. 버그 개수 평균은 비슷하다.
- 같은 libexif 하나, 반복 10번이라 일반화는 못 한다.

## 3. 실험 3: 단계별 정보를 준 LLM이 입력 생성 (`exif/llm_chat-A_*`)

- LLM: ChatGPT Go (모델 버전 미기록), 단계별 프롬프트를 각 1회 새 대화에 붙여넣어 입력 10개씩 받음 (`llm/prompts/L*.txt`, 응답 원문 `llm/raw/chat-A_L*_1.txt`)
- 비교 기준: 같은 단계 퍼저 10분 평균

| 단계 | LLM 입력 | LLM 누적 edge | 퍼저 평균 edge | LLM crash | 위치 |
|---|---|---|---|---|---|
| L0 | 10 | 106 | 154.0 | 0 | |
| L1 | 10 | 198 | 154.0 | 1 | `exif_log` (`exif_loader_write` 경유) |
| L2 | 10 | 246 | 441.5 | 0 | |
| L3 | 10 | 241 | 479.2 | 0 | |

해석
- L1에서 LLM은 입력 10개로 퍼저(10분)보다 높은 edge에 도달했고 crash도 냈다. L2, L3에서는 퍼저가 훨씬 깊이 들어간다 (입력 수와 시간 차이).
- L3가 L2보다 낫지 않았다.
- LLM의 L1 crash 입력 `ffd8ffe1 0008 41424344 ffd9`(가짜 APP1 구간)는 `exif_log`에서 죽는다. 퍼저 L0~L3의 전 실행(L0, L1 각 3번 + L2, L3 각 10번)에서 이 위치는 나오지 않았다. 입력 하나, 응답 한 번이라 단정은 못 한다.
- 주의: L1 프롬프트의 `FF D8 FF E1`만으로도 큰 모델은 EXIF라는 것을 안다. L1 응답에도 `Exif`, `II*`가 들어 있다. 단계별 정보 차이가 LLM에서는 깨끗하게 분리되지 않는다.

작은 모델(qwen2.5:3b, 로컬 Ollama) 관찰: 서로 다른 입력을 지시하지 않은 첫 프롬프트에서 L3 응답 10줄이 전부 프롬프트의 유효 샘플을 그대로 복사했다(서로 다른 입력 1개). "서로 다르게, 예시와도 다르게" 문장을 모든 단계에 똑같이 넣고 temperature를 1.0으로 올리자 10개가 모두 달랐다. 한 번 호출에 100~140초.

## 4. 실험 2: 퍼저 결과와 LLM 입력의 중복 제거 비교 (`exif/cmp_chat-A_*`)

퍼저 쪽은 같은 단계 반복 1~3번의 queue와 crashes를 합친 것. 중복 제거 순서: LLM 입력끼리 edge 집합이 같은 것 제거 → 퍼저가 이미 가진 edge 집합과 같은 것 제거 → 남은 것만 분석.

| 단계 | 퍼저 파일 | LLM 입력 | 자체 중복 제거 후 | 퍼저와 중복 제거 후 | 남은 것 중 새 edge를 여는 입력 | 남은 것 중 crash |
|---|---|---|---|---|---|---|
| L0 | 282 | 10 | 2 | 0 | 0 | 0 |
| L1 | 289 | 10 | 8 | 5 | 3 | 1 |
| L2 | 1331 | 10 | 10 | 9 | 1 | 0 |
| L3 | 1323 | 10 | 10 | 9 | 0 | 0 |

edge 집합 비교

| 단계 | 퍼저만 | 겹침 | LLM만 |
|---|---|---|---|
| L0 | 50 | 106 | 0 |
| L1 | 24 | 132 | 66 |
| L2 | 226 | 243 | 3 |
| L3 | 258 | 241 | 0 |

해석
- L0: LLM 입력 10개 중 8개가 같은 코드 경로를 밟아 중복이고, 남은 2개도 퍼저가 이미 도달한 곳이다. 중복 제거가 의미 있게 작동한다.
- L1: 퍼저가 시그니처만으로 못 넘는 부분을 LLM이 열었다(LLM만 연 edge 66개). 보완 관계가 보이는 유일한 단계.
- L2, L3: LLM이 연 edge는 거의 전부 퍼저가 이미 갖고 있다.

## 5. 한계 (보고서에 그대로 쓸 것)

1. 타깃이 libexif 하나이고 숨은 버그가 적다(위치 기준 3곳 + LLM 1곳).
2. LLM 결과는 단계당 응답 1회(입력 10개)뿐이다. 통계 검정이 불가능하다. ChatGPT Go 외 모델, 작은 로컬 모델 결과는 아직 없다(로컬 Ollama 진행 중).
3. 큰 LLM은 단계 정보 외에도 사전 지식으로 EXIF 구조를 안다. 단계 차이가 LLM에서 완전히 분리되지 않는다.
4. 단계 정의 자체가 우리가 정한 것이다.
5. 퍼저 쪽 crash 구분은 "신호 + 맨 위 함수"이다. 이름이 없는 내부 함수는 `+0xad03` 같은 오프셋으로 나오고, 빌드가 바뀌면 오프셋도 바뀐다.
6. 처음의 합성 타깃(tinyfmt, `tinyfmt/`)은 파이프라인 검증용이다. 계단형 결과(L0=L1=0, L2 서로 다른 버그 2, L3 4~5)는 버그를 그렇게 심어서 나온 것이므로 논문 결과가 아니다.
