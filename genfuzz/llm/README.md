# 2번·3번 실험: LLM이 만든 입력 vs 퍼저

- `fzlib.py` 공통 도구(edge 얻기: afl-showmap 폴더 모드, crash 위치 분류, 16진수 파싱)
- `gen_llm.py` 단계(L0~L3)별 프롬프트 → LLM(로컬 Ollama 또는 채팅창 붙여넣기) → 입력 파일
- `llm_eval.py` (3번) LLM 입력을 타깃에 실행: 누적 edge, crash, 버그. 같은 단계 퍼저(10분) 평균과 같은 축에서 비교
- `llm_vs_fuzz.py` (2번) 같은 단계의 퍼저 결과와 나란히 놓고 edge 집합 기준으로 중복 제거 후 남은 것만 분석

중복 판단은 파일 내용이 아니라 '밟은 edge 집합'이 같은지로 한다.
단계 정의는 퍼징(1번)과 같다: L0 정보 없음 / L1 JPEG 시그니처 / L2 L1 + 필드 구조 / L3 L2 + 유효 샘플 1개.

## 관찰 기록
- 첫 시도(프롬프트에 '서로 다르게' 지시 없음): qwen2.5:3b, L3, 1회 응답 INPUT 10줄 전부 프롬프트의 유효 샘플을 그대로 복사 → 서로 다른 입력 1개.
  이후 모든 단계 프롬프트에 '서로 다르게, 예시와도 다르게' 문장을 똑같이 넣고 temperature 1.0 으로 올렸다.
- `preview_sandbox_*` 는 개발용 샌드박스 빌드(계측 방식이 달라 edge 수가 다름)로 파이프라인만 확인한 미리보기다. 논문 숫자가 아니다. 최종 결과는 WSL2 빌드로 만든 `llm_<태그>.png`, `llm_<태그>_summary.csv` 를 쓴다.
